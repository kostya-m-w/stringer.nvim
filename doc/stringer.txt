*stringer.txt*  Ordered codepaths for Neovim                         *stringer*

Stringer 0.4 requires Neovim 0.10 or newer. No dependencies.

==============================================================================
QUICK START                                                 *stringer-start*

Open a saved code file, then: >
    :Stringer new request-flow
    :Stringer add
<
Visit other locations and add marks. Paths can span repositories. >
    :Stringer next
    :Stringer prev
    :Stringer show
<
In the dedicated pane: <CR> jumps, dd removes, K/J move up/down, u undoes,
r renames, R reloads, and q closes. Mark changes save immediately.

==============================================================================
COMMANDS                                                 *:Stringer*

:Stringer new [name]     Create and activate; prompt if no name supplied.
:Stringer open [name]    Activate, or choose with vim.ui.select. If no paths
                        exist, prompt to create one. Cancelling is harmless.
:Stringer rename [name]  Rename active codepath; prompt if no name supplied.
:Stringer add            Append current file and line; save immediately.
:Stringer show           Open/focus the dedicated right-side pane.
:Stringer next           Next mark, wrapping last to first.
:Stringer prev           Previous mark, wrapping first to last.
:Stringer remove         Remove selected mark and save.
:Stringer move-up        Move selected mark one position up and save.
:Stringer move-down      Move selected mark one position down and save.
:Stringer undo           Undo last append, removal, or move and save.
:Stringer reload         Reload active codepath from disk; clear undo history.
:Stringer skip           Toggle skipped state and save.
:Stringer hide-skipped   Toggle visibility of skipped marks (view only).
:Stringer note           Edit selected mark's multiline note.
:Stringer import [name]  Import whole current buffer into a new codepath.
:Stringer import-report  Show last import's results and excluded frames.
:Stringer cancel-import  Cancel pending lookup or import prompt.

Names use letters, numbers, hyphens, and underscores. Creating and renaming
reject existing names. One codepath is active at a time. No global mappings
are installed. Subcommands and saved path names have completion.

From the pane, mark actions use its cursor row; from code, they use the active
mark. Mark movement does not wrap, unlike navigation. Opening a path does not
jump automatically. Closing its pane keeps the path active.

==============================================================================
ACTIVE MARK AND NAVIGATION                                *stringer-navigation*

The nearest enabled marked line in the focused code file determines the active mark.
This updates on cursor movement and file/window focus changes. Equal-distance
ties preserve the current entry if tied, otherwise choose the earlier entry
in codepath order. No maximum distance or Tree-sitter integration is used.

An unmarked file preserves the previous active mark. With no active mark, next
starts at the first entry and previous at the last. Duplicate locations remain
independently navigable. The pane shows the active mark with a highlight and >
sign; moving its cursor alone does not change the active mark.

Navigation uses the current code window. From the pane, it uses the last focused
code window in the same tab, or another eligible code window. If none exists,
open one first. Navigation honors 'hidden' and modified-buffer safeguards.

==============================================================================
CONFIGURATION                                            *stringer-setup*

Setup is optional: >lua
    require('stringer').setup({
      storage_dir = vim.fn.stdpath('data') .. '/stringer/paths',
      pane_width = 48,
      gutter = true,
      gutter_sign = 'o',
      gutter_note_sign = 'N',
      gutter_priority = 10,
      inline_notes = true,
      symbol_labels = true,
    })
<
storage_dir             Independent cross-repository codepath storage.
pane_width              Initial pane width, a positive integer in columns.
gutter                  Show source signs for the active codepath.
gutter_sign             Ordinary-mark sign; one or two display cells.
gutter_note_sign        Sign for a line with at least one noted mark.
gutter_priority         Nonnegative sign priority; default 10.
inline_notes            Automatically expand notes below the active entry.
symbol_labels           Use imported frame/LSP titles when available.
StringerActive          Active-mark highlight, defaults to Visual.
StringerNote            Inline note highlight, defaults to Comment.
StringerGutter          Ordinary source signs, defaults to Special.
StringerGutterActive    Active source signs, defaults to Search.
StringerGutterSkipped   All-skipped source signs, defaults to Comment.

==============================================================================
MARK VIEW AND RECOVERY                                    *stringer-editing*

The pane is noneditable. Its local mappings are:
    <CR>    Jump to selected mark.
    dd      Remove selected mark.
    K / J   Move selected mark up/down; cursor follows the moved entry.
    u       Undo the last mark change, persisting the restored state.
    r       Prompt to rename the active codepath.
    R       Reload from disk.
    s       Toggle skipped state and save immediately.
    H       Hide/reveal skipped marks.
    n       Edit a multiline note.
    q       Close pane without deactivating the path.

Each entry has two rows: a contextual title and a filename/line location.
Locations use the shortest distinguishing trailing path suffix. Long paths are
shortened from the left so their endings and line numbers remain useful. Widths
are measured in display cells. Shared pane buffers use the narrowest visible
pane's available width. Persisted paths stay absolute.

Imported method/function labels are preferred when recognizable. Otherwise an
already attached LSP may supply an enclosing function/method, including reliable
class/module context from hierarchical document symbols. Filename is the
fallback. No files are loaded and no language servers started just for labels.
Flat declaration-only symbol results do not imply an enclosing method. Set
symbol_labels=false for filename-only titles. Tree-sitter is not required.

Both base rows and all note rows map to their owning mark. Enter, dd, K/J, s,
and n work from any such row. Reflow preserves mark ownership under the cursor.

Append, remove, move, skip, and undo save immediately. Failed writes leave the marks,
pane, history and stored file unchanged. Reordering preserves the active entry;
removing it clears the active mark until navigation or proximity selects another.
Undo restores the previous mark list and active index.

Undo history is in memory and clears when opening/reloading a path. Renaming
preserves history but is not itself undone by u. There is no redo.

External changes block mutations instead of being overwritten. Reload with R
or :Stringer reload. Invalid files report record line numbers and preserve the
last valid runtime state. Save/discard drafts in manually opened raw storage
buffers first. Content comparison is not a multi-process locking protocol.

==============================================================================
SKIPPED MARKS                                            *stringer-skipped*

Skipped marks remain stored but are excluded from proximity and next/previous
navigation. They display [skip] and StringerSkipped highlighting (Comment by
default). Explicit Enter jumps are allowed. All-skipped navigation reports an
error without looping. The header shows total, skipped, and hidden counts.

Hiding is a view preference, preserved across pane close/reopen and rename, but
reset on path open/reload. Filtered K/J moves a mark before/after its adjacent
visible neighbor, preserving hidden entries' relative order. Hidden marks are
never deleted by filtering. A hidden active mark is indicated in the header.

==============================================================================
MULTILINE NOTES                                          *stringer-notes*

Use n or :Stringer note for a Markdown editor. :write saves; :wq saves and closes
only on success. Empty content removes the note. q closes a saved editor;
:bwipeout! discards a draft explicitly. Opening another note will not replace
an unsaved draft.

The active mark's full note expands directly beneath its location row, preserving
blank lines and wrapping long lines. Another active mark replaces this section;
marks without notes show none. Pane cursor movement alone does not change which
note is expanded. Hidden marks do not have orphaned note sections. Notes display
read-only Markdown source; set inline_notes=false to disable automatic expansion.
The separate note editor and its modified state are unaffected by reflow.

Each save is an undoable mark mutation. If marks change while editing (including
reordering, skipping, undo, or path reload), the editor refuses a stale save.
Copy the draft, discard its editor, reopen the intended note, and paste it back.
Navigation, view changes, and rename do not invalidate the draft. Failed saves
preserve its modified flag and content.

==============================================================================
SOURCE GUTTER SIGNS                                      *stringer-gutter*

Only the active codepath has source signs: o for ordinary marks and N if a mark
on the line has a note. Multiple marks at one location share a sign. Active
membership selects the active highlight; otherwise the group is dimmed only
when all its marks are skipped. Hide-skipped affects the list, not source signs.

Signs are placed only in loaded code buffers. Stale lines past EOF are not
clamped. Signs are reconciled to the stored line numbers after source edits;
they do not relocate persisted marks. Switching paths removes obsolete signs.

Stringer respects existing signcolumn/statuscolumn settings and other plugin
namespaces. Enable a signcolumn if your layout hides signs. Adjust gutter_priority
or available sign columns to coexist with diagnostics/Git signs. Set gutter=false
to disable source indicators.

==============================================================================
STACKTRACE IMPORT                                        *stringer-import*

Paste one conventional trace into a buffer and run :Stringer import [name].
The entire buffer is captured, including scratch/log/terminal buffers. Omit the
name to prompt. Import creates a new path, retaining source text and quickfix.

Supported syntax: conventional Ruby path:line:in and from frames; V8/Node
JavaScript/TypeScript at function (path:line:column) or at path:line:column;
standard Java at package.Class.method(File.java:line).

Frames are reversed from deepest-first to outermost-available caller first.
Duplicate and framework frames remain. The original frame text is stored as
context separately from notes and supplies contextual titles when recognizable.

Local absolute paths are used directly. Relative paths use the captured cwd Git
root (or cwd if no Git root). Local file:/// URIs are accepted. Java basenames
are found with a project-local .java index, narrowed by package when possible;
only unique matches resolve. Large searches yield and support cancel-import.

Missing/ambiguous sources, native frames and unsupported locations are reported
with source line numbers. Partial imports are labeled and open a report; use
import-report to reopen it. No resolved frames means no new file. Stored lines
past EOF still fail at navigation time with the ordinary stale-mark error.

Chained/suppressed exceptions, elided chains, interrupted/multiple stacks, and
outermost-first Ruby tracebacks are rejected. Remote remapping, source maps,
browser-specific traces and other import sources/destinations are deferred.
TypeScript source locations must already be present in the trace.

==============================================================================
FORMAT AND COMPATIBILITY                                  *stringer-format*

Versions 0.3 and 0.4 share the same storage format. Rendering and symbol lookup
do not mutate marks or create undo history.

Existing 0.1/0.2 paths load without rewriting. New paths and the next successful
mutation use mark version 2. Storage remains JSON Lines: >
    {"type":"stringer","format_version":1,"mark_version":2}
    {"file":"/workspace/service/main.lua","line":42,"note":"First\nSecond"}
<
Optional fields: boolean skipped, string note, string frame (import context).
Missing skipped means false. Multiline strings are escaped in JSON, preserving
one physical line per mark. Old plugin versions reject mark version 2.
Format versions are independent of plugin releases. Marks require absolute
paths and positive one-based integer line numbers. Duplicate marks and empty
(header-only) paths are valid. Blank records, extra fields, relative paths,
invalid JSON, and unsupported versions are rejected. Final newlines are valid.

The pane no longer exposes raw JSON editing or :write. Use explicit mark actions.

References are fixed: code edits do not relocate marks. Missing files and lines
past EOF report errors without changing the active mark. Files must have been
saved before marking; modified buffers record the current cursor line.

Active path, position and undo history are not restored across restarts. Use
:Stringer open. Split navigation, Tree-sitter-based selection, automatic mark
relocation, and fish-eye view are deferred.

==============================================================================
LUA API                                                  *stringer-api*

require('stringer') exposes:
    setup(opts)
    new(name?), open(name?), rename(name?), reload()
    add(), show(), next(), prev(), jump(index)
    remove(index?), move_up(index?), move_down(index?), undo()
    skip(index?), hide_skipped(), note(index?)
    import(name?), import_report(), cancel_import()

Indices address the full stored list, including hidden marks, and are one-based.
Omitted action indices use the selected/active mark.
Operations return true or nil, error and notify failures. Prompting functions
return before the asynchronous selection completes. setup errors on invalid
options. Import returns before asynchronous lookup/prompt completion; results
are reported through notifications and the import report.
