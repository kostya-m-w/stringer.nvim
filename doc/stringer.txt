*stringer.txt*  Ordered codepaths for Neovim                         *stringer*

Stringer 0.9 requires Neovim 0.10 or newer. No plugin dependencies.
Git provenance uses the optional git executable.

==============================================================================
QUICK START                                                 *stringer-start*

Open a saved code file, then: >
    :Stringer new request-flow
    :Stringer add
<
Visit other locations and add marks. Paths can span repositories. >
    :Stringer next
    :Stringer prev
    :Stringer show
<
In the dedicated pane: <CR> jumps, dd removes, K/J move up/down, u undoes,
r renames, R reloads, and q closes. Mark changes save immediately.

==============================================================================
COMMANDS                                                 *:Stringer*

:Stringer new [name]     Create and activate; prompt if no name supplied.
:Stringer open [name]    Activate, or choose with vim.ui.select. If no paths
                        exist, prompt to create one. Cancelling is harmless.
:Stringer rename [name]  Rename active codepath; prompt if no name supplied.
:Stringer copy [name]    Copy to a new name, remaining on the original path.
:Stringer directory [path]
                        Select/create storage directory, or report locations.
:Stringer move [directory]
                        Move the active path, retaining its name and state.
:Stringer add            Append current file and line; save immediately.
:Stringer show           Open/focus the dedicated right-side pane.
:Stringer next           Next mark, wrapping last to first.
:Stringer prev           Previous mark, wrapping first to last.
:Stringer remove         Remove selected mark and save.
:Stringer move-up        Move selected mark one position up and save.
:Stringer move-down      Move selected mark one position down and save.
:Stringer undo           Undo last append, removal, or move and save.
:Stringer reload         Reload active codepath from disk; clear undo history.
:Stringer skip           Toggle skipped state and save.
:Stringer hide-skipped   Toggle visibility of skipped marks (view only).
:Stringer note           Edit selected mark's multiline note.
:Stringer refresh-snapshot
                        Capture/replace the selected mark's source snapshot.
:Stringer import [name]  Import whole current buffer into a new codepath.
:Stringer import-report  Show last import's results and excluded frames.
:Stringer cancel-import  Cancel pending lookup or import prompt.
:Stringer fisheye        Open/focus the dedicated fish-eye tab.
:Stringer fisheye-close  Close fish-eye mode and return to its origin.
:Stringer fisheye-range {previous} {next}
                        Set independently requested neighbor counts.
:Stringer fisheye-notes  Toggle all fish-eye note subsplits.
:Stringer fisheye-refresh
                        Retry targets, rebuild and recenter the view.

Names support spaces, Unicode and filesystem-compatible punctuation. Quote
multiword command arguments with either single or double quotes: >
    :Stringer new "Investigate payment retry failures"
    :Stringer rename 'Retry analysis'
<
Prompts take literal names without wrapping quotes. Old unquoted single-token
names remain valid. Within quotes, escape a matching quote or backslash with a
backslash; other backslashes stay literal. Empty names, surrounding whitespace,
separators and control characters are rejected. Arguments are never shell code.
Creation/rename reject existing destinations. Completion supports quoted names
and directory arguments. One codepath is active; no global mappings are installed.

From the pane, mark actions use its cursor row; from code, they use the active
mark. Mark movement does not wrap, unlike navigation. Opening a path does not
jump automatically. Closing its pane keeps the path active.

==============================================================================
ACTIVE MARK AND NAVIGATION                                *stringer-navigation*

The nearest enabled marked line in the focused code file determines the active mark.
This updates on cursor movement and file/window focus changes. Equal-distance
ties preserve the current entry if tied, otherwise choose the earlier entry
in codepath order. No maximum distance or Tree-sitter integration is used.

An unmarked file preserves the previous active mark. With no active mark, next
starts at the first entry and previous at the last. Duplicate locations remain
independently navigable. The pane shows the active mark with a highlight and >
sign; moving its cursor alone does not change the active mark.

Navigation uses the current code window. From the pane, it uses the last focused
code window in the same tab, or another eligible code window. If none exists,
open one first. Navigation honors 'hidden' and modified-buffer safeguards.

==============================================================================
CONFIGURATION                                            *stringer-setup*

Setup is optional: >lua
    require('stringer').setup({
      storage_dir = vim.fn.stdpath('data') .. '/stringer/paths',
      pane_width = '40%',
      gutter = true,
      gutter_sign = '->',
      gutter_priority = 10,
      inline_notes = true,
      footer = true,
      fisheye_previous = 2,
      fisheye_next = 2,
      fisheye_notes = true,
      fisheye_note_width = '35%',
    })
<
storage_dir             Startup storage directory; change runtime selection
                        with :Stringer directory.
pane_width              Percentage ('1%' to '99%'), or positive integer columns.
                        Default '40%'. Keep room for at least 40 code columns
                        where possible; Neovim may further constrain splits.
gutter                  Show source signs for the active codepath.
gutter_sign             Shared mark sign; one or two display cells.
gutter_note_sign        Deprecated no-op, accepted for old configurations.
gutter_priority         Nonnegative sign priority; default 10.
inline_notes            Automatically expand notes below the active entry.
footer                  Show the compact, always-visible key/action footer.
fisheye_previous        Requested previous marks; nonnegative integer.
fisheye_next            Requested next marks; nonnegative integer.
fisheye_notes           Initial session-global fish-eye notes visibility.
fisheye_note_width      Columns or percentage of each code+notes row.
symbol_labels           Deprecated no-op; previews always show source text.
StringerActive          Background-only active-mark highlight.
StringerNote            Inline note highlight, defaults to Comment.
StringerGutter          Ordinary source signs, yellow by default.
StringerGutterActive    Active source signs, bold yellow by default.
StringerGutterSkipped   All-skipped source signs, subdued yellow by default.

==============================================================================
MARK VIEW AND RECOVERY                                    *stringer-editing*

The pane is noneditable. Its local mappings are:
    <CR>    Jump to selected mark.
    dd      Remove selected mark.
    K / J   Move selected mark up/down; cursor follows the moved entry.
    u       Undo the last mark change, persisting the restored state.
    r       Prompt to rename the active codepath.
    R       Reload from disk.
    s       Toggle skipped state and save immediately.
    H       Hide/reveal skipped marks.
    n       Edit a multiline note.
    c       Capture/refresh the selected mark's source snapshot and save.
    ?       Open Stringer help.
    q       Close pane without deactivating the path.

Each entry has two rows: a captured source line and a filename/line location.
Every first row starts with a downward arrow (↓), including skipped entries.
Location and inline-note rows are indented beneath it without another arrow.
Locations use the shortest distinguishing trailing path suffix. Long paths are
shortened from the left so their endings and line numbers remain useful. Widths
are measured in display cells. Shared pane buffers use the narrowest visible
pane's available width. Persisted paths stay absolute.

The selected codepath name appears in a styled persistent winbar. The metadata
row shows its actual storage directory and a different browsing directory when
applicable. :Stringer directory shows full locations; ? opens help.

Adaptive widths follow editor resizing. Manual widths are remembered per tab
across close/reopen during the session, and clamped if the editor becomes too
narrow. setup({pane_width=...}) resets manual preferences and applies that value.

Active-mark changes from code navigation do not auto-scroll or focus the pane.
Refreshes preserve cursor ownership and viewport content as structural changes
permit. Explicit pane operations may move selection to their result.

Source text replaces method/filename titles even for imported marks. LSP symbol
lookups are no longer performed. Imported frame context is still stored.
Tree-sitter evaluation remains future work.

Both base rows and all note rows map to their owning mark. Enter, dd, K/J, s,
n, and c work from any such row. Reflow preserves mark ownership under the cursor.

Append, remove, move, skip, and undo save immediately. Failed writes leave the marks,
pane, history and stored file unchanged. Reordering preserves the active entry;
removing it clears the active mark until navigation or proximity selects another.
Undo restores the previous mark list and active index.

Undo history is in memory and clears when opening/reloading a path. Renaming
preserves history but is not itself undone by u. There is no redo.

External changes block mutations instead of being overwritten. Reload with R
or :Stringer reload. Invalid files report record line numbers and preserve the
last valid runtime state. Save/discard drafts in manually opened raw storage
buffers first. Content comparison is not a multi-process locking protocol.

==============================================================================
KEY/ACTION FOOTER                                        *stringer-footer*

A compact footer remains at the bottom while the list scrolls and while focus
is in code. It also works in the fish-eye path pane. Example: >
    Enter jump · n note · c capture · s skip · ? help
<
Hints adapt to the window width, retaining ? for the complete reference. Wider
footers show H hide skipped or H show skipped according to the filter state.
Use the same keys in the pane; the footer itself is informational chrome, not
an editable or selectable mark row.

Visible per-window statuslines carry the hints natively. If laststatus selects
a global or hidden statusline, a non-focusable footer occupies the bottom of the
pane instead, with padding so final mark/note rows remain reachable. Global
statusline options are never changed. Leaving the pane restores its previous
local statusline. Set footer=false to disable the hints.

? opens this full reference, including dd remove, K/J move, u undo, r rename,
R reload, H hide/reveal skipped marks, and q close.

==============================================================================
STORAGE DIRECTORIES AND MOVING                           *stringer-directory*
                                                        *stringer-move*

Use :Stringer directory [path] to select/create a ticket-specific storage
directory. Leading ~/ is expanded; relative paths use the cwd captured when the
operation starts. Cwd itself is not changed. Selection is session-wide and
survives unrelated setup calls; explicitly setting storage_dir changes it.

New, named open, import, copy destinations and the picker use the selected
directory. Existing records keep their actual file identity: saves, reload,
rename, undo, notes and snapshots never follow a later directory switch. Prompts
and asynchronous imports bind their destination directory when they start.

:Stringer directory without an argument reports the browsing directory and full
active filename. Same-named paths in different directories are independent.

:Stringer move [directory] keeps the filename, active record, bytes, history,
metadata, note drafts and fish-eye state. It selects the destination on success;
moving to the same canonical directory is a no-op. Missing directories are
created, but failed moves leave the previous browsing selection intact.

Collisions, raw storage-buffer drafts, stale prompts and external source-file
changes block movement. Cross-filesystem movement stages and verifies a complete
destination before removing the original. Publication never overwrites another
file. Failed removal attempts rollback only if the destination still matches
what this operation created; otherwise both retained locations are reported.
Cross-filesystem moves are not atomic and can leave a duplicate after interruption.
These content/identity checks are not multi-process locks. Close a destination
raw storage buffer if both source and destination buffers are already open.

==============================================================================
GIT CREATION PROVENANCE                                  *stringer-git*

New marks record full repository HEAD and repository-relative filename when
available. Discovery starts from each marked file, not cwd. Worktrees, detached
HEAD and nested repositories are supported. Imports use the checkout observed
at import time, not a historical commit inferred from the trace.

The commit does not represent unsaved/uncommitted changes or guarantee that an
untracked file exists in it. Source snapshots still record actual captured text.
Original Git metadata is immutable through snapshot refresh, note/skip edits,
reorder, copy, move and rename. Old marks are not backfilled.

Missing Git, no repository, or unborn HEAD permit capture without provenance.
Other lookup errors/timeouts notify and omit metadata. Git lookup is asynchronous
and bounded. Rapid adds preserve invocation order and the original cursor/text;
switching/reloading the active path cancels pending adds. A browsing-directory
switch alone cannot retarget an active record. Imports batch lookups by repository
and retain cancellation behavior.

==============================================================================
FISH-EYE VIEW                                            *stringer-fisheye*

:Stringer fisheye opens one managed tab with a right-side path pane and ordered
source rows to its left. The active mark is the largest MAIN row, with up to two
previous and two next rows by default. Reopening focuses the same tab.

Heights fall off by the golden ratio (approximately 1.618) per step from main,
subject to minimum window sizes and integer rounding. Short screens omit the
farthest previews first; they return when space permits. Boundaries show fewer
rows without duplicates or fillers. Explicit next/prev navigation stays cyclic.

Use normal Stringer next/prev and path-pane Enter. Focusing a preview promotes
its mark to main before editing. Source buffers are shared and their modifiable/
readonly flags are not changed. Mouse and Ctrl-W navigation both promote rows.
Cursor motion inside code does not run proximity selection in fish-eye mode.
Ordinary tabs retain their normal behavior.

Each marked line is centered on navigation and highlighted per window, so marks
in the same file can have different highlighted target lines. Typing does not
continually recenter/rebuild the view. A line made stale during editing is flagged;
explicit refresh/navigation retries resolution. The path pane does not auto-scroll.

All skipped marks are excluded from neighbors, even when visible in the list.
Explicit jumps can still select a skipped main mark. Empty/all-skipped paths get
an explanatory main placeholder when there is no explicit anchor.

Asymmetric ranges preserve path order: >
    :Stringer fisheye-range 4 0
    :Stringer fisheye-range 3 1
    :Stringer fisheye-range 0 0
<
The first puts MAIN at the bottom. Both counts accept zero and persist for the
session, including across view close/reopen and temporary screen reductions.

Nonempty notes have read-only windows to the right of their code row, enabled
by default. fisheye-notes toggles them all and retains the preference across
close/reopen. This does not affect inline notes in the path pane or stored data.
Notes windows can be focused for scrolling/copying; Enter promotes their code
mark, and n opens the existing note editor. Narrow layouts temporarily suppress
panels without disabling the global preference.

Missing/unreadable files and stale lines use labeled placeholders, including
MAIN. fisheye-refresh retries after sources are fixed. Ordinary-tab navigation
continues to report errors without jumping to unavailable targets.

Rebuilds and close honor modified-buffer and destructive bufhidden safeguards.
Save blocked buffers or use a nondestructive hidden-buffer policy to proceed.
Source buffers are never force-discarded; unsaved note-editor drafts are preserved.

fisheye-close returns to the origin when possible. If no other tab exists, it
creates an ordinary empty tab. Closing a preview is reconciled; manually closing
the entire tab never recreates it. Replacing a managed source window with user
content ends management and preserves windows/edits. Enter fish-eye mode again
explicitly when desired.

There is still one global active path. Changes made outside fish-eye mode are
reconciled on return, without background tab/focus changes. View actions do not
write codepaths or alter undo history. Highlight groups: StringerFishMain,
StringerFishPreview, and StringerFishLine (background-only source-line highlight).

==============================================================================
SOURCE SNAPSHOTS                                         *stringer-snapshots*

Add captures the current full logical source line, including unsaved edits.
Import captures resolved source lines where available. Snapshots preserve leading
and trailing whitespace but omit line terminators. Display trims indentation
and truncates long lines without changing stored text or exact comparison.

    [changed]      Current text differs; preview still shows the saved snapshot.
    [uncaptured]   No snapshot; show current text until explicitly captured.
    [missing]      File or stored line no longer exists.
    [unreadable]   Read/encoding failure or non-file path.
    [checking]     Asynchronous source read pending.

Empty/whitespace-only previews display (blank line). Captured empty text differs
from never captured. Uncaptured marks may also be missing/unreadable; they have
no baseline to compare as changed. Missing sources retain saved previews.

Use c or :Stringer refresh-snapshot to accept current text for one mark. It saves
through normal mutation/undo handling. Identical refreshes are no-ops. Failures
and stale asynchronous results preserve the old snapshot. Snapshot refresh is a
mark mutation, so open note drafts follow the usual revision-conflict behavior.

Prefer loaded buffers, including unsaved edits; otherwise read disk without
opening a buffer. A deleted file is missing even if its buffer remains loaded.
Disk reads handle UTF-8 BOM and LF/CRLF. Unsupported encodings are unreadable;
a loaded buffer can supply Neovim-decoded text. Source changes, pane show, and
focus return refresh comparisons. External edits to unloaded files are detected
at these points, not through continuous filesystem watching.

Comparison never writes the codepath or changes snapshots/undo history. It does
not relocate a moved statement: navigation still uses the stored file/line.

==============================================================================
COPY CODEPATHS                                           *stringer-copy*

:Stringer copy [name] creates a new path with all saved marks and metadata,
including absent/empty snapshots, notes, skipped state and frame context. It does
not recapture source. The original stays active with unchanged selection and
history. Opening the copy later starts fresh runtime state and undo history.

Omit name to prompt. Existing names, dirty raw storage buffers and externally
changed source codepath files block copying. A stale name prompt is rejected if
the source path/marks changed. Unsaved note-editor drafts remain intact but are
not copied; the last saved note is used. Cancellation and write failures do not
alter the original path.

==============================================================================
SKIPPED MARKS                                            *stringer-skipped*

Skipped marks remain stored but are excluded from proximity and next/previous
navigation. They display [skip] and StringerSkipped highlighting (Comment by
default). Explicit Enter jumps are allowed. All-skipped navigation reports an
error without looping. The header shows total, skipped, and hidden counts.

Hiding is a view preference, preserved across pane close/reopen and rename, but
reset on path open/reload. Filtered K/J moves a mark before/after its adjacent
visible neighbor, preserving hidden entries' relative order. Hidden marks are
never deleted by filtering. A hidden active mark is indicated in the header.

==============================================================================
MULTILINE NOTES                                          *stringer-notes*

Use n or :Stringer note for a Markdown editor. :write saves; :wq saves and closes
only on success. Empty content removes the note. q closes a saved editor;
:bwipeout! discards a draft explicitly. Opening another note will not replace
an unsaved draft.

The active mark's full note expands directly beneath its location row, preserving
blank lines and wrapping long lines. Another active mark replaces this section;
marks without notes show none. Pane cursor movement alone does not change which
note is expanded. Hidden marks do not have orphaned note sections. Notes display
read-only Markdown source; set inline_notes=false to disable automatic expansion.
The separate note editor and its modified state are unaffected by reflow.

Each save is an undoable mark mutation. If marks change while editing (including
reordering, skipping, undo, or path reload), the editor refuses a stale save.
Copy the draft, discard its editor, reopen the intended note, and paste it back.
Navigation, view changes, and rename do not invalidate the draft. Failed saves
preserve its modified flag and content.

==============================================================================
SOURCE GUTTER SIGNS                                      *stringer-gutter*

Only the active codepath has source signs: the same yellow -> with and without
notes. Multiple marks at one location share a sign. Active
membership selects the active highlight; otherwise the group is dimmed only
when all its marks are skipped. Hide-skipped affects the list, not source signs.

Signs are placed only in loaded code buffers. Stale lines past EOF are not
clamped. Signs are reconciled to the stored line numbers after source edits;
they do not relocate persisted marks. Switching paths removes obsolete signs.

Stringer respects existing signcolumn/statuscolumn settings and other plugin
namespaces. Enable a signcolumn if your layout hides signs. Adjust gutter_priority
or available sign columns to coexist with diagnostics/Git signs. Set gutter=false
to disable source indicators.

==============================================================================
STACKTRACE IMPORT                                        *stringer-import*

Paste one conventional trace into a buffer and run :Stringer import [name].
The entire buffer is captured, including scratch/log/terminal buffers. Omit the
name to prompt. Import creates a new path, retaining source text and quickfix.

Supported syntax: conventional Ruby path:line:in and from frames; V8/Node
JavaScript/TypeScript at function (path:line:column) or at path:line:column;
standard Java at package.Class.method(File.java:line).

Frames are reversed from deepest-first to outermost-available caller first.
Duplicate and framework frames remain. The original frame text is stored as
context separately from notes; the pane shows captured source instead.

Local absolute paths are used directly. Relative paths use the captured cwd Git
root (or cwd if no Git root). Local file:/// URIs are accepted. Java basenames
are found with a project-local .java index, narrowed by package when possible;
only unique matches resolve. Large searches yield and support cancel-import.

Missing/ambiguous sources, native frames and unsupported locations are reported
with source line numbers. Partial imports are labeled and open a report; use
import-report to reopen it. No resolved frames means no new file. Stored lines
past EOF still fail at navigation time with the ordinary stale-mark error.

Capture warnings are separate from exclusions. A resolved mark whose source line
cannot be captured is retained without a snapshot and reported as a warning.
Source reads are batched; cancelling during capture creates no path.

Chained/suppressed exceptions, elided chains, interrupted/multiple stacks, and
outermost-first Ruby tracebacks are rejected. Remote remapping, source maps,
browser-specific traces and other import sources/destinations are deferred.
TypeScript source locations must already be present in the trace.

==============================================================================
FORMAT AND COMPATIBILITY                                  *stringer-format*

Versions 0.8 and 0.9 share mark format v4. Footer rendering does not modify
codepaths, mark selection, notes or undo history.

Moving/renaming preserves original file bytes and format. View changes never
alter saved metadata or history.

Versions 0.1-0.7 load without rewriting or guessing historical provenance.
New paths and the next successful content mutation use mark version 4. Untouched
old marks retain absent metadata. Storage remains JSON Lines: >
    {"type":"stringer","format_version":1,"mark_version":4}
    {"file":"/workspace/service/main.lua","line":42,"snapshot":"  handle()"}
<
Optional fields: boolean skipped, string note, string frame (import context),
and single-line string snapshot. Optional git metadata contains both commit (a
full 40/64-character hexadecimal object ID) and path (a repository-relative source
filename without traversal). Absent snapshot means uncaptured; snapshot=""
captures a blank line. Older plugin versions reject mark version 4.
Missing skipped means false. Multiline strings are escaped in JSON, preserving
one physical line per mark. Rendering/comparison never mutates stored marks.
Format versions are independent of plugin releases. Marks require absolute
paths and positive one-based integer line numbers. Duplicate marks and empty
(header-only) paths are valid. Blank records, extra fields, relative paths,
invalid JSON, and unsupported versions are rejected. Final newlines are valid.

The pane no longer exposes raw JSON editing or :write. Use explicit mark actions.

References are fixed: code edits do not relocate marks. Missing files and lines
past EOF report errors without changing the active mark. Files must have been
saved before marking; modified buffers record the current cursor line.

Active path, position and undo history are not restored across restarts. Use
:Stringer open. Tree-sitter-based selection, automatic mark relocation, and
runtime execution contexts remain deferred.

==============================================================================
LUA API                                                  *stringer-api*

require('stringer') exposes:
    setup(opts)
    new(name?), open(name?), rename(name?), copy(name?), reload()
    directory(path?), move(directory?)
    add(), show(), next(), prev(), jump(index)
    remove(index?), move_up(index?), move_down(index?), undo()
    skip(index?), hide_skipped(), note(index?)
    refresh_snapshot(index?)
    import(name?), import_report(), cancel_import()
    fisheye(), fisheye_close(), fisheye_range(previous, next)
    fisheye_notes(), fisheye_refresh()

Indices address the full stored list, including hidden marks, and are one-based.
Omitted action indices use the selected/active mark.
Operations return true or nil, error and notify failures. Prompting functions
return before the asynchronous selection completes. setup errors on invalid
options. Git-backed add, import and disk-backed snapshot refresh can return before asynchronous
completion. Errors are notified; import details are available in its report.
